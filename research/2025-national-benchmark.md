# 2025 年国赛公开作品 benchmark

## 资料边界

2025 年公开可检索的传智杯大模型/AI 应用作品资料比较分散，官方公开页面没有提供一个可直接下载的完整国赛作品集。本记录只纳入能看到公开仓库 README 或明确作品说明的案例；没有公开证据的名次、数量和评委评价不作推断。

## 已核对案例：Intelligent-Chat-Robot

- 仓库：[hlx923/Intelligent-Chat-Robot](https://github.com/hlx923/Intelligent-Chat-Robot)
- README 自述：参加 2025 年传智杯人工智能大模型创新应用挑战赛，获得“国家一等奖”。这是作者自述，最终材料仍应以组委会公布结果为准。
- 产品形态：多模态智能聊天助手。
- 可见能力：本地 Ollama 模型（Qwen2、DeepSeek-R1）、文本/语音/图片输入、情感分析、自动模型选择、多语言支持。
- 交互形态：Streamlit 工作台，侧边栏可选择模型、调参数和语言，输入区支持上传图片和语音。
- 工程证据：README 列出了 `app.py`、模型管理、语音识别、错误处理和响应处理模块，且明确写出本地运行依赖和回退语音识别方案。

## 对 CampusFlow 的启发

1. **多模态必须形成任务闭环**：图片、语音本身不是亮点，亮点在于输入后触发了可观察的计划、工具或审核结果。CampusFlow 将截图/PDF 输入连接到证据定位和任务依赖，而不是停在聊天回复。
2. **本地/离线回退增强评审稳定性**：公开案例把 Ollama 作为核心路径。CampusFlow 保留无 API Key 的演示模式，并把真实模型作为服务端适配器；评委始终能走通完整流程。
3. **模型路由要可解释**：自动模型选择可以展示 Agent 决策，但必须显示选择原因、失败回退和耗时。CampusFlow 会把 Retriever、Planner、工具检查和 Reviewer 作为可观察事件展示。
4. **README 和运行说明是作品的一部分**：公开案例能让评审快速理解技术栈和启动方式。CampusFlow 需要继续补齐真实模型配置、数据契约、固定评测和部署健康检查。
5. **避免做同质化聊天框**：多模态聊天助手是强参考，也是拥挤方向。CampusFlow 的差异放在“证据—约束—任务 DAG—人工确认”四件事同屏，并用合成资料保证可公开演示。

## 不应复制的内容

不复制该项目的代码、README 文案、模型配置、截图或业务设计。它只用于研究公开能力组合和评审可见证据；CampusFlow 使用独立的数据、视觉和代码实现。

## 结论

目前能可靠核对的 2025 公开样本支持一个方向：国赛级作品需要“多模态 + 本地/可控模型 + 可运行工作台 + 清晰工程说明”的完整证据链。它不能证明某个单一技术栈必然获奖，也不能替代正式评审规则。
