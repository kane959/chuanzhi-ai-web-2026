# 提交前门禁

## 资格与赛道

- [ ] 队员 1–3 人，来自同一所学校；指导老师不超过 2 人。
- [ ] 参赛组别与学校层级匹配。
- [ ] 赛道为 `AI WEB网页开发挑战赛`，没有误报为其他赛道。
- [ ] 个人中心、缴费和最终提交入口已核对官方通知。

## 代码仓库

- [ ] GitHub/Gitee 仓库公开或已给评审访问权限。
- [ ] README 有项目价值、技术架构、安装运行、环境变量、团队信息、演示地址。
- [ ] `.env`、API Key、个人隐私和真实学号不在 Git 历史中。
- [ ] Git 提交历史真实，提交信息能说明阶段性工作。
- [ ] `pnpm lint`、`pnpm typecheck`、`pnpm build` 和 Playwright E2E 通过。
- [ ] 许可证和第三方依赖清单完整。

## AI 能力

- [ ] LLM 结构化输出有 schema 校验和失败回退。
- [ ] Agent 计划、工具调用、工具结果、最终回答在 UI 可见。
- [ ] RAG 回答有来源、定位、相关度；没有依据时明确拒答。
- [ ] 至少一个多模态输入完成从解析到计划的闭环。
- [ ] 工具参数白名单、超时、重试、限流和审批点已测试。
- [ ] 演示模式不冒充真实模型，真实模式不依赖前端共享密钥。

## 体验与部署

- [ ] 1080p 屏幕与移动宽度可用；键盘和减少动画偏好可用。
- [ ] 首屏、空状态、加载、错误、无依据和工具失败都有可理解的反馈。
- [ ] 公网演示无需私人账号；如必须登录，提供评审账号和复位方式。
- [ ] 健康检查和日志正常；评审期间有保活/告警。

## 视频与文档

- [ ] 演示视频 5–8 分钟、MP4、≥1080p、普通话/字幕。
- [ ] 视频依次覆盖：问题、用户流程、AI 深度、创新交互、失败兜底、在线地址。
- [ ] PDF ≤30 页，含需求、架构、AI 选型/集成/优化、实现、测试部署、创新点、局限和展望。
- [ ] 视频、PDF、README 中项目名称、版本、队员和地址一致。
- [ ] 截止前至少 24 小时上传并保存回执；提交后不再改动材料。
