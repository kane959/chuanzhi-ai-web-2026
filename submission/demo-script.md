# CampusFlow 参赛演示视频稿

建议成片时长：5 分 30 秒至 6 分 30 秒。画面录制 1920×1080，旁白语速保持每分钟 220 至 260 字。旁白中的“这里”对应鼠标当前停留位置；涉及真实模型、官网同步和部署的状态，必须按录制当天实际结果替换。

## 片头：问题与答案（0:00–0:35）

**画面**：展示 CampusFlow 首页“使用说明”，随后切到工作台。标题、Logo 和三步流程保持在画面中央。

**旁白**：

“新生入学时，校园卡、宿舍报修、奖助材料往往分散在不同通知和系统里。真正困难的不是找到一条信息，而是判断这条信息是否支持当前事项、下一步要做什么、材料是否齐全，以及时间是否冲突。CampusFlow 是一个可查证的校园事务行动协同智能体。它把事项输入、资料检索、行动排期和人工审核放在一条流程里，让用户先看到依据，再决定是否执行。”

## 使用说明与隐私边界（0:35–1:00）

**画面**：停留在“使用说明”，依次指向“从一件事开始”“资料导入的范围”“执行前由你确认”。

**旁白**：

“首次打开先看到使用说明。用户只需要记住三步：输入事项，选择时间，查看清单。当前演示使用通用合成校园资料，不代表任何学校官方通知。任务进度只保存在本机；提交申请、写入日历和发送提醒都需要用户确认。系统找不到依据时会明确提示，不会用模型编造校园事实。”

## 第一步：输入一个真实任务（1:00–1:35）

**画面**：点击“工作台”，在输入框输入：

> 我周三下午有空，想处理宿舍漏水，还要领取校园卡，需要准备什么？

点击“下一步：选择时间”。

**旁白**：

“现在输入一个新生常见的复合任务：宿舍漏水，同时领取校园卡。系统会把一句自然语言目标交给 Planner，识别事项、时间约束和需要核验的材料。用户也可以导入文本通知，或者从示例开始体验。”

## 第二步：选择时间与自定义时间（1:35–2:05）

**画面**：展示上午、下午、晚上、周末和“自定义时间”五个选项。选择“自定义时间”，设置 16:00；再切回“工作日下午”，强调两种方式都可用。

**旁白**：

“第二步是时间约束。系统提供上午、下午、晚上、周末四类常用时段，也支持自定义时间。这里选择 16 点。时间不是装饰信息：线下校园卡窗口在 17 点关闭，系统会根据开放时间标记可安排或待协调，而线上报修可以在更宽的时间范围内完成。”

## 第三步：Planner、RAG 与 Reviewer（2:05–2:55）

**画面**：点击“生成我的行动计划”。录制加载过程：理解目标、召回依据、排期检查、Reviewer 审核、等待确认。等待结果完成。

**旁白**：

“点击生成后，页面展示五个可追踪阶段。第一阶段解析目标；第二阶段从校园资料包中召回相关依据；第三阶段检查开放时间和事项冲突；第四阶段由 Reviewer 做安全审核；最后把结果交给用户确认。这里的检索结果会显示资料编号、标题、定位和原文摘要，相关度只是召回排序，不代表模型置信度。”

“如果资料不足、时间冲突、必备材料缺失，Reviewer 会把结果标记为需要人工确认或阻止确定性结论。它的作用是限制系统越权，而不是替用户做最终决定。”

## 查看行动清单与时间冲突（2:55–3:35）

**画面**：展示左侧行动卡片和右侧事项详情。点击“领取校园卡”，再点击“提交宿舍报修”。重点展示时间、地点、冲突说明和原因。

**旁白**：

“结果页把长文本拆成行动卡片。每张卡片包含事项、预计时长、建议时间、地点和当前状态。领取校园卡属于线下事项，如果选择晚间或自定义到 17 点以后，系统会显示‘待协调’，并说明窗口关闭时间和对应依据。宿舍报修属于线上事项，会单独排期。用户可以先处理不冲突的步骤，再回到需要协调的事项。”

## 查看证据与原文定位（3:35–4:10）

**画面**：在右侧“支持这一步的依据”中点击 E-03 或 E-06，点击“打开原文定位”，展示抽屉中的来源、定位、更新时间和引用段落。

**旁白**：

“每一个行动都能回到依据。点击支持这一步的资料，可以看到来源地址、文档编号、原文定位、更新时间和引用段落。这样评委和用户都能区分三件事：资料原文是什么，系统根据它安排了什么，以及哪些地方仍然需要人工核对。官网单页同步开启后，导入的页面会以待核验证据加入资料库，并保留原文链接。”

## 材料清单与本地添加（4:10–4:45）

**画面**：在“材料清单”中点击“添加材料”，选择一个演示用文本或图片文件；展示文件名出现、项目自动勾选。再点击“问题描述”复选框，展示本地状态变化。

**旁白**：

“右侧是材料清单。必备材料和按需材料分开显示，已经核对的项目会实时计数。点击‘添加材料’可以从本机选择文件，系统将该项标记为已准备，并显示文件名；当前演示只保留页面状态，不会自动上传或提交。用户仍可以手动勾选，适合先整理材料，再决定是否进入真实办理入口。”

## Reviewer 与失败路径（4:45–5:15）

**画面**：回到审核横幅，展示“需要人工确认”；可选地输入一个没有匹配资料的目标，展示“暂未找到足够依据”。

**旁白**：

“CampusFlow 的安全边界也体现在失败路径里。当目标没有匹配到资料，页面会明确说明没有足够依据，保留人工核对入口，而不是生成看似完整的答案。当服务端或真实模型不可用时，系统显示连接失败或回退到演示 Planner，并保留来源和审核状态。任何外部提交都停在用户确认之前。”

## 导出与结尾（5:15–6:00）

**画面**：点击“导出清单”，展示导出前确认弹窗、材料缺项和时间冲突统计，点击“确认下载”。最后回到首页三步流程，或展示 GitHub Pages 在线地址。

**旁白**：

“导出前，系统再次汇总行动数量、待补材料和时间冲突。用户可以继续检查，也可以下载 Markdown 清单。导出的内容会保留建议排期、材料勾选、依据编号和冲突说明，不会写入日历，不会发送消息，也不会替用户提交申请。”

“CampusFlow 的核心不是替人做决定，而是把分散资料变成可追溯的行动建议：有依据就引用，有冲突就解释，没依据就停下来等待确认。谢谢观看。”

## 录制检查清单

- 片头先展示“使用说明”，再进入“工作台”。
- 录制前确认页面中的后端状态、官网同步状态和模型模式与旁白一致。
- 使用合成资料或已获授权的公开通知，不在画面中展示真实学号、身份证号、手机号或 API Key。
- 展示自定义时间、时间冲突、原文定位、材料添加、Reviewer 和导出确认六个关键证据。
- 如果当天后端未部署完成，旁白改为“演示模式可运行，服务端接口已预留”，不要说成真实模型或官网同步已经上线。
