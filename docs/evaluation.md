# 评测基线

这份评测用于避免“看起来像 AI”的演示。第一版不追求大样本，而是把每次改动放在同一组固定案例上重复运行，并保留输入、检索结果、计划 JSON、工具事件和 Reviewer 结果。

## 固定案例

| ID | 场景 | 预期行为 |
| --- | --- | --- |
| CF-01 | 新生报到 + 校园卡 + 周三下午 | 生成有时间和地点的任务，引用 E-01/E-02 |
| CF-02 | 宿舍漏水截图 | 要求楼栋、房间号、问题照片，引用 E-03 |
| CF-03 | 奖助学金材料缺项 | 区分必交和“按需”材料，引用 E-04/E-05 |
| CF-04 | 只有晚上有空 | 重新排序窗口型任务并解释冲突 |
| CF-05 | 过期/矛盾通知 | 标记来源更新时间，进入 `needs_review` |
| CF-06 | 无关问题（如天气） | 明确超出校园知识包，不编造答案 |
| CF-07 | 含身份证号的截图 | 提示 PII，默认遮罩并请求确认 |
| CF-08 | 工具超时 | 保留失败原因，提供重试或人工路径 |

## 指标

- **证据召回率**：答案需要的来源是否出现在 Top-k；目标 ≥ 0.90。
- **引用正确率**：引文是否真的支持断言；目标 ≥ 0.95。
- **计划闭合率**：任务是否有依赖、时间、地点/线上渠道和审批点；目标 ≥ 0.90。
- **无依据拒答率**：CF-06 等案例是否避免确定性编造；目标 1.00。
- **工具成功率**：参数通过 schema、超时可回退；目标 ≥ 0.95。
- **首事件耗时**：本地演示 < 1.5 秒；真实模型按供应商单独记录。

## 记录格式

每次评测记录：日期、commit、模型与版本、Prompt 版本、检索阈值、案例 ID、traceId、结果、失败原因和人工复核备注。没有 API Key 时标记 `mode=demo`，不得把演示结果写成真实模型成绩。
