# CampusFlow / 通用校园行动 OS 产品简报

## 一句话

把一条校园通知、一张办事截图或一句“我想在周五前办完这些事”，变成可查证、可调整、需要人确认才执行的行动计划。

## 为什么从通用校园行动切入

附件问卷给出了两个可用信号：在 32 份有效回答中，84.38% 的人访问 AI 网站是为了解决具体问题；在 17 份回答中，64.71% 偏好互动体验/娱乐站。CampusFlow 将两者合并：用真实办事闭环提供价值，用任务地图、时间线和“如果改日期会怎样”的互动提供记忆点。样本量小、来源是用户提供的截图，只作为选题假设，不冒充正式市场调研。产品不绑定广州航海学院或任何特定学校。

附件视频显示了两类视觉参考：约 590 秒的非遗纸艺作品网站，强调内容叙事与视觉展示；约 350 秒的健康管理看板，强调数据概览、趋势和任务分区。我们的界面同时借鉴“叙事首页 + 工作台看板”，但不复制素材或页面。

## 首个可演示任务

> “我刚入学，想在本周五前完成校园卡、宿舍报修和奖助学金材料准备；我只有周三下午有空，哪些需要本人到场？”

系统应：

1. 从校园知识包检索政策、地点、时间和材料要求，并显示原文定位。
2. 让 Planner 把自然语言目标拆成任务和依赖，标记必须本人到场的步骤。
3. 调用日历冲突检查、校园地图/开放时间、材料完整性检查等工具。
4. 让 Reviewer 检查截止时间、来源冲突、隐私和不确定项。
5. 以“计划时间线 + 证据卡 + 材料清单 + 下一步按钮”呈现；写入日历或导出材料前必须由用户确认。

## 三个核心界面

- **任务入口**：文字、图片/PDF、拖放上传；先显示解析状态和隐私提示。
- **行动工作台**：左侧计划时间线，中间任务卡和材料勾选，右侧原文证据/置信度/工具调用。
- **情景推演**：拖动日期或更换“只有晚上有空”等条件，展示计划如何变化，支持一键回滚；它是互动记忆点，也能证明 Agent 不是一次性聊天。

## AI 不是附属功能

知识检索决定事实边界；Agent 决定任务分解、工具选择和顺序；多模态理解负责从截图/PDF 中提取信息；Reviewer 负责冲突和安全；模型只在证据和工具结果范围内生成解释。没有 AI 时仍能运行本地演示流程，但会明确标注“演示模式”。

## 数据与边界

第一版使用自建的合成校园资料：通知、服务指南、开放时间、材料清单和地点均带有 `sourceId`、更新时间和定位字段。它们用于稳定演示检索、规划和审核链路，不冒充任何学校的官方通知。后续接入真实学校时，必须由授权方提供脱敏资料，并单独建立来源和过期策略。

## 差异化假设

当前可见竞品已经覆盖“通知 → 清单”“通用 Agent + RAG”“论文引用核查”“自然语言数据分析”。CampusFlow 的差异不是再做一个聊天框，而是把 **政策证据 + 时间/地点约束 + 材料依赖 + 人类审批** 放到同一个可视化行动系统里，并允许替换学校知识包。展示前必须用自建数据和测试证明这些差异，不用竞品 README 的自评结论。

## 非目标

省赛第一版不做支付、自动提交任何学校系统、保存真实身份证/学号、全量学校接入或开放任意 MCP 写操作。所有副作用都走“预览 → 用户确认 → 可撤销”链路。
