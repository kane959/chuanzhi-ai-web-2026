# CampusFlow 前端迭代方案

日期：2026-10-28。

## 设计决定

把产品的核心放在“这一周能做什么”：左侧常驻导航，中间目标和行动队列，右侧当前事项的材料与依据。通知纸张、材料夹和日程线是视觉语汇，主画面就是能操作的计划。原来的大幅轨道图不能解释实际任务，予以移除。

颜色：页面灰绿 `#f5f7f6`，工作区白色 `#ffffff`，正文深绿 `#193b31`，主要操作 `#26765a`，辅助薄荷 `#eaf3ee`，冲突琥珀 `#a86614`。主标题和控件使用系统中文无衬线字体，数字采用等宽数字，不依赖远程字体。正文 14–16 px，辅助文字原则上至少 12 px。圆角区分输入、卡片和容器，不给所有区域相同权重。

```text
导航 | 顶栏：工作区 / 知识库搜索 / 演示模式
     | 标题 + 可交互的周日程
     | 目标输入       行动队列                当前事项
     | 本地文件       时间约束                材料 / 证据
     | 例子           可追踪规划              原文抽屉
     |                冲突解释与恢复          确认导出
```

手机端保留主要任务，导航折叠到顶部菜单；输入、计划、详情按操作顺序排列。知识库、原文与导出使用原生模态对话框，支持 Esc、焦点回归、键盘和触摸。

## 可验证的功能改进

- 计划阶段展示本地检索、排期和检查产生的真实结果，明确是规则演示；取消会终止本次运行。
- 晚间约束直接改变排期：线下校园卡窗口在 17:00 关闭，不能编造晚上/次日可用时间；显示待协调。
- 未找到依据时不生成当前问题的计划，清楚区分之前的示例计划。
- 材料勾选和任务进度保存在带版本的本地存储中，不持久化输入或文件内容。
- 原文定位打开实际合成资料并高亮引用段落；检索分数取本次结果，不把固定分数当模型置信度。
- 导出前展示时间、缺项和冲突，再由用户确认下载本地 Markdown。
- 文本通知支持本地读取；图片/PDF 明确提示解析尚未接入。

## GitHub 参考的取舍

采用 `anthropics/skills/frontend-design` 的设计计划与浏览器自审方法；采用 `vercel-labs/agent-skills` 的版本化本地存储、派生状态和无障碍规范。研究 AG-UI 的运行状态/工具结果事件、assistant-ui 的运行与取消、shadcn/ui 的交互语义、xyflow 的依赖表达。目前无需引入这些完整框架，保持 React/Vite 轻量闭环。

这些参考支持本次通用校园场景，不改变产品方向，不引入参赛学校资料。所有页面代码、资料和插画独立实现。
